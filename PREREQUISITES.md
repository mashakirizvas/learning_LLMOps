# Пре-реквізити: перевір себе до старту курсу

Мета цього файлу — щоб перший урок ти витратив на курс, а не на боротьбу з
оточенням. Пройди три блоки нижче; на все разом — 15–20 хвилин.

## 1. Система

| Що | Мінімум | Як перевірити |
|---|---|---|
| ОС | Windows 10/11, macOS або Linux — будь-що, де працює Docker | — |
| Docker + Compose **2.24+** | будь-який дистрибутив (Docker Desktop, Engine, Rancher Desktop…) | `docker --version` і `docker compose version` |
| Git | будь-яка свіжа версія | `git --version` |
| Диск | ~4 ГБ вільного місця під образи | — |
| RAM | ~4 ГБ вільної пам'яті для контейнерів | — |
| Порти | вільні `4200`, `8080`, `4000`, `5432` | див. блок 3 |
| Інтернет | потрібен на перший запуск (тягне образи); далі курс працює офлайн | — |

> **Чому саме 2.24.** `docker-compose.yml` підключає ключі провайдерів через
> `env_file` з `required: false` — довгу форму, яка з'явилася у Compose 2.24.0.
> На старішій версії стек не підніметься взагалі, з помилкою розбору YAML.
> Той самий поріг потрібен і для зсуву портів (блок 3). Compose оновлюється
> разом із Docker Desktop.

Платні API-ключі **не потрібні**: вся обов'язкова доріжка працює на
mock-провайдері. Реальний ключ — суто опційна історія (урок 1, опційна секція).

**Опційно: GUI до бази.** Лаби постійно просять SELECT-и до лога, і в консолі
це швидко набридає — широкі таблиці ламаються по рядках, історію запитів
доводиться перегортати. Якщо зручніше мишею, постав будь-який клієнт до
PostgreSQL, наприклад [DBeaver Community](https://dbeaver.io/download/)
(безкоштовний, Windows/macOS/Linux) або pgAdmin. Параметри підключення —
у блоці 5 гайда.
Обов'язковим це не є: `psql` уже всередині контейнера, і всі команди в
завданнях дано саме для нього, щоб вони працювали в будь-кого.

## 2. Акаунти і навички

**GitHub-акаунт** — обов'язково: домашні завдання здаються PR-ами у твоєму
репозиторії, а на тижні 6 CI-гейт працює у GitHub Actions (безкоштовного
ліміту Actions для курсу достатньо). Свій репозиторій зі стартера створиш
за інструкцією [GETTING_STARTED, §12 крок 0](GETTING_STARTED.md#12-здача-домашок-і-перевірка) —
це 5 хвилин, можна зробити вже зараз. Бонус: цей репозиторій після курсу
залишається тобі — готовий портфельний проєкт.

**Навички** (курс не про програмування, але код читати доведеться):

- читаєш простий C# (методи, if, словники) — писати з нуля не треба:
  всі місця підписані `TODO(student, W#)`;
- читаєш простий Python (evals — один файл на stdlib);
- базовий SQL: `SELECT`, `WHERE`, `GROUP BY`;
- git: clone, branch, commit, push, відкрити PR;
- не боїшся термінала (Windows: команди курсу — у Git Bash, він іде разом із Git).

Якщо чогось із цього бракує — курс прохідний, але заклади +1–2 години на
тиждень на догугл.

## 3. Самоперевірка за 10 хвилин

Виконай по черзі; кожна команда має відпрацювати без помилок.

```bash
docker --version          # Docker version 2x.x
docker compose version    # v2.x — саме "docker compose", не "docker-compose"
git --version
```

Перевір, що порти вільні (має бути порожній вивід):

```bash
# macOS / Linux
lsof -i :4200 -i :8080 -i :4000 -i :5432
```

```powershell
# Windows (PowerShell) — дивись ЛИШЕ на рядки LISTENING по цих портах;
# рядки TIME_WAIT/ESTABLISHED і "схожі" порти (:42005) — не завада
netstat -ano | findstr "LISTENING" | findstr ":4200 :8080 :4000 :5432"
```

Якщо якийсь порт зайнятий — його можна зсунути (`demo-ports.yml`; деталі —
блок 8 гайда, «Troubleshooting»). Зсув тримається
на тегу `!override`, який з'явився у Compose 2.24. На старішій версії тег мовчки
ігнорується, порти не замінюються, а **додаються** — і зайнятий порт лишається
зайнятим. Поводиться це як «зсув не спрацював без причини». Перевірка:

```bash
docker compose version    # має бути >= 2.24
```

Найчастіший винуватець зайнятого `5432` — свій PostgreSQL, встановлений
раніше: він стартує сам і тримає порт. Зупинити його службу зазвичай простіше,
ніж зсувати весь стек.

І фінальний смоук — підняти стек курсу:

```bash
git clone https://gitlab.com/taras_fedorenko/llmops-bootcamp-starter.git
cd llmops-bootcamp-starter
docker compose up --build
```

Перший запуск тягне образи — це нормально. Коли вщухне, відкрий
`http://localhost:4200`: ліворуч чат, праворуч консоль із «—» у плитках.
Напиши боту «Як скинути пароль?» — прийшла відповідь → ти готовий(-а),
побачимось на уроці 1. Стек можна погасити: `docker compose down`.

## Типові граблі (щоб не втрачати перший вечір)

- **Порт зайнятий.** Найпідступніший варіант: на порту вже сидить інший
  локальний сервіс і чемно відповідає своїми 404 — усе «ніби працює», але не
  наше. Перевіряй обидва стеки: `http://localhost:8080/health`,
  `http://127.0.0.1:8080/health` і `http://[::1]:8080/health` мають віддавати
  той самий `{"status":"ok"}`. Якщо ні — звільни порт або зміни мапінг у
  `docker-compose.yml`.
- **Корпоративний проксі.** Запити до `localhost` не мають ходити через
  проксі; додай `localhost,127.0.0.1,::1` у `NO_PROXY`. (Наш eval-runner уже
  обходить проксі сам — але браузер і curl можуть впертися.)
- **Кирилиця в терміналі.** Якщо у виводі кракозябри — переведи термінал на
  UTF-8 (Windows: `chcp 65001` або Windows Terminal).

Повний розбір цих і інших проблем — у
[GETTING_STARTED, розділ Troubleshooting](GETTING_STARTED.md#8-troubleshooting).
