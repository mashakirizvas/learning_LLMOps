## Спільні правила здачі

- ДЗ живе у **твоєму** репозиторії (клон стартера — GETTING_STARTED, §12 крок 0) і після курсу залишається тобі як портфельний проєкт.
- Здача = гілка + Pull Request у власному репо. CI на PR ганяє evals і червоніє на регресії. Здача — це не лише код: описи рішень у PR (hw3) і README-розділи (hw6) — такі самі артефакти перевірки.
- Репозиторій — публічний, або приватний із ментором у колабораторах. Посилання на PR кидаєш у канал потоку курсу; перевірка — 2–3 доби від здачі.
- Дедлайн здачі — PR **протягом тижня від моменту, коли ти отримав(-ла) ДЗ** (тобто від другого уроку тижня); пізніші PR перевіряються за SLA наступного тижня. Дедлайн однаковий для всіх тижнів, зокрема для пікових **W4 і W6** — їх просто розкладай на два підходи всередині тижня (для W4: reliability → safety); це закладено в дизайн, не аврал.
- Вердикт ментора — **«зараховано»** або **«на доопрацювання»** з максимум трьома головними зауваженнями (решта — інлайн-коментарі в код).
- Кожне наступне ДЗ гілкуй від `main` **після мержа попереднього** — інакше в diff буде минулий тиждень і перевірка сповільниться.
- Evals ганяються командою з GETTING_STARTED §6; до уроку 10 використовуй runner як чорну скриньку.
- Застряг? Еталонні рішення є, але не роздаються разом зі стартером: доступ відкриває ментор **за запитом**. Політика проста: спершу власна спроба, потім звірка — еталон учить лише після того, як ти сам(-а) вперся(-лась).
- В описі PR — що зробив і скрін консолі.
- Місця в коді підписані `TODO(student, W#)` у `service/Program.cs`.
- Все робиться на mock, без реального ключа.
- Орієнтир по часу: 2–3 години після guided lab. Виходить суттєво більше — неси
  питання в канал потоку, не закопуйся.
- Критерії перевірки в кожному ДЗ відкриті — ментор дивитиметься саме на них, і під час потоку вони не змінюються.
